# 微信与企业微信平板登录（纯 Zygisk）

v3.1.0 是独立 Zygisk 模块，让手机上的微信、企业微信出现平板扫码登录入口。无需 LSPosed 或配套 APK；其他 LSPosed 模块可继续使用。仅在两个应用主进程调整平板判定与企业微信的登录设备身份，不修改全局 DPI、分辨率或应用数据。

## 下载与安装

安装 `dist/tablet-spoof-pure-v3.1.0.zip`，在 root 管理器安装，确认 Zygisk 已启用，然后重启。已发布的版本见 [Release](https://github.com/2909272751/tablet-spoof/releases)。

**不再限制应用版本号**：企业微信按稳定签名识别并提供代码回退；微信通过 DEX 语义特征和调用关系识别，适应混淆名称变化。仅支持 arm64。未知版本也会尝试识别，无法确认时保留原行为并记录失败，不保证所有未来实现都兼容。

1. 停用旧的 `io.github.tabletspoof` LSPosed 模块，避免重复替换；其他 LSPosed 模块无需关闭。
2. 打开应用登录页，点击「平板和手机同时登录」，用已登录账号的主手机扫码并授权。
3. root 管理器「操作」按钮先导出诊断日志，再开关模块。开关后强停并重新打开应用即可，不清除数据。
4. 停用或卸载本模块并重启即可恢复。

## 验证结果

实测环境：小米 9 / Android 16、APatch 114027、Zygisk Next 1.5.0。当前手机为微信 8.0.78、企业微信 5.0.11。实机验证按整个 LSPosed 关闭后的「关 → 开」对照确认入口与实际替换调用；测试结束恢复 LSPosed。

企业微信 5.0.11 已验证扫码、主手机确认和进入企业全部成功；本次补齐内部设备身份，修复“确认后仍卡在登录中”，并处理启动时换类加载器导致重启失效。用户确认主副机同时在线，LSPosed 开启时重新打开仍保持登录，关闭框架后整机重启也直接进入消息页。微信 8.0.78 验证了损坏缓存自动恢复和平板入口；首次识别及安装实测约 4.2–5.4 秒。系统维持 1080 × 2340、440 DPI、SELinux Enforcing；设置应用没有加载新引擎。自动验证不代表所有账号的双端在线或长期稳定性已经覆盖。

应用可能依据平板判定自行调整部分页面，保持系统 DPI 不等于保证所有内部界面布局相同。
